# STM32 → Luckfox → Ubuntu 完整操作手册

> 三端（STM32 / Luckfox / Ubuntu 虚拟机）的逐步操作，从零到端到端跑通。
> 目标链路（单向）：`STM32 → USART2 → Luckfox → Wi-Fi(TCP) → Ubuntu 虚拟机`。

---

## 0. 总体流程 & 网络拓扑

```
┌──────────────┐  USART2(PA2 TX)   ┌────────────────────┐   Wi-Fi(TCP:9000)   ┌───────────────┐
│  STM32F407   │ ────────────────▶ │  Luckfox Pico Ultra W│ ─────────────────▶ │ Ubuntu 22.04 VM│
│  (Keil烧录)   │  3.3V + 共地      │  (Buildroot Linux)   │                    │   (nc 看数据)  │
└──────────────┘                   └────────────────────┘                    └───────────────┘
```

**关键网络说明：**
- Ubuntu 虚拟机要能访问到 Luckfox 的 IP。**推荐把虚拟机网卡设成「桥接(Bridged)」模式**，让 VM 和 Luckfox 处在同一个局域网。
- 若用 NAT 模式，VM 也能主动连 Luckfox（`nc` 是 VM 主动发起），所以也能用；只是桥接更省心。
- Luckfox 先连上家里的 Wi-Fi，拿到局域网 IP（形如 `192.168.x.y`），之后 VM 靠这个 IP 去 SSH 和收数据。

## 1. STM32 操作

### 1.1 CubeMX 加 USART2

1. 打开 `RemoteMonitoringSystem.ioc` → **Connectivity → USART2** → Mode = **Asynchronous**
2. 波特率 **115200**、8N1（与 USART1 相同）
3. 引脚自动分配：**PA2 = USART2_TX**、PA3 = USART2_RX（本方案只用 TX）
4. **GENERATE CODE** 重新生成（会多出 `huart2` / `MX_USART2_UART_Init()`）

> 你的任务属性已经搬进 `USER CODE` 块了，放心生成，不会覆盖。

### 1.2 `freertos.c` 新增发送任务（4 处，都放 USER CODE 块内）

**① 顶部 Includes（`USER CODE BEGIN Includes`）加：**
```c
#include <stdio.h>
#include "usart.h"
```

**② 任务属性（放进你刚搬好的 `USER CODE BEGIN Variables` 块，放在 `keyTask_attributes` 后面）：**
```c
osThreadId_t uartTxTaskHandle;
const osThreadAttr_t uartTxTask_attributes = {
	.name = "uartTxTask",
	.stack_size = 256 * 4,
	.priority = (osPriority_t) osPriorityNormal,
};
```

**③ 函数原型（`USER CODE BEGIN FunctionPrototypes`）：**
```c
void StartUartTxTask(void *argument);
```

**④ 创建任务（`USER CODE BEGIN RTOS_THREADS`）：**
```c
uartTxTaskHandle = osThreadNew(StartUartTxTask, NULL, &uartTxTask_attributes);
```

**⑤ 任务体（`USER CODE BEGIN Application`）：**
```c
void StartUartTxTask(void *argument)
{
  char buf[64];
  monitor_data_t d;
  int n;

  for(;;)
  {
    osMutexAcquire(g_monitor_mutex, osWaitForever);   /* 拿笔 */
    d = g_monitor;                                    /* 复制整份快照 */
    osMutexRelease(g_monitor_mutex);                  /* 放笔 */

    n = snprintf(buf, sizeof(buf), "T=%d,H=%d,L=%d,S=%d\r\n",
                 d.temperature, d.humidity, d.light, d.dht11_ok);
    HAL_UART_Transmit(&huart2, (uint8_t*)buf, (uint16_t)n, 100);

    osDelay(1000);   /* 每秒发一次 */
  }
}
```

### 1.3 编译烧录

Keil → Rebuild → 下载到 STM32F407。烧录后 STM32 会每 1 秒从 PA2 发出一行 `T=...,H=...,L=...,S=...`。

### 1.4 接线（重点：共地！）

| STM32（探索者 F407） | Luckfox Pico Ultra W |
|---|---|
| **PA2** (USART2_TX) | **UART3_RX_M0** |
| **GND** | **GND** |

- 两侧都是 **3.3V**，直接连，**无需电平转换**
- **GND 必须共地**，否则收到全是乱码
- 单向发送，RX 不用接

## 2. Luckfox 操作（第一次初始配置，只做一次）

> 初始配置需要先能进到 Luckfox 的 shell，通常走 **USB RNDIS SSH**（板子自带），或 **串口调试台**。

### 2.1 登录（USB RNDIS SSH）

Luckfox 的 USB 口插入电脑后，会虚拟出一个 USB 网卡（RNDIS），板子固定 IP **172.32.0.93**。

- **登录信息**（Buildroot）：用户名 `root`，密码 `luckfox`
- 在 Mac/VM 上给这个 USB 网卡配个同网段地址，例如 `172.32.0.98/24`，然后：
  ```bash
  ssh root@172.32.0.93   # 密码 luckfox
  ```

> 在 Ubuntu 虚拟机里用 USB，需先在虚拟机设置里把 USB 设备「直通」给 VM（VMware: 可移动设备→连接；VirtualBox: 设备→USB）。嫌麻烦也可以直接在 **Mac 终端** 里 SSH 完成本节初始配置，之后的日常运行再回到 VM。

> 找不到 USB 网卡设备名？`ip link` 看多出来的那个接口（可能叫 `usb0` / `enx...`），再 `sudo ip addr add 172.32.0.98/24 dev <接口名>`。

### 2.2 配置 Wi-Fi（推荐 `wpa_supplicant` 方式）

1. 编辑 `/etc/wpa_supplicant.conf`，写入你的 Wi-Fi：
   ```
   ctrl_interface=/var/run/wpa_supplicant
   ap_scan=1
   update_config=1

   network={
       ssid="你的WiFi名字"
       psk="你的WiFi密码"
       key_mgmt=WPA-PSK
   }
   ```
2. 重启 Wi-Fi 并获取 IP：
   ```bash
   killall -9 wpa_supplicant
   wpa_supplicant -B -i wlan0 -c /etc/wpa_supplicant.conf
   udhcpc -i wlan0
   ```
3. 查 IP：
   ```bash
   ip addr show wlan0     # 或 hostname -I
   ```

> 备选：也可以用 `luckfox-config` 的菜单配置 Wi-Fi。若发现 Wi-Fi 连不上，检查是否有 `rkwifi_server` 进程在抢：`ps -ef | grep rkwifi_server`，有就 `killall rkwifi_server` 再试。

### 2.3 开启 UART3（`/dev/ttyS3`）

1. 运行配置工具：
   ```bash
   luckfox-config
   ```
2. 进 **Advanced Options → UART → UART3 → enable**（方向键/回车/空格切换）
3. 验证：
   ```bash
   luckfox-config show    # 看 UART3 是否已启用
   ls /dev/ttyS*          # 应能看到 /dev/ttyS3
   ```
> UART3 使能后通常立即生效；个别情况要重启板子。

### 2.4 确认运行环境（Python 或 socat，二选一）

```bash
# 检查 python3 + pyserial
python3 -c "import serial"        # 报错则: pip install pyserial（若 pip 也没有，看 2.5）

# 或检查 socat（零代码备选）
which socat
```

### 2.5 若 Buildroot 镜像没有 python3/pip

Luckfox 的 Buildroot 镜像可能默认不带 Python。两条路：
- **装 Python**：用 Luckfox 官方提供的 Python 环境/包，或 `opkg` 安装（按官方文档）。
- **换 socat**：如果镜像里有 socat，直接走第 3.2 节的 socat 方案，**完全不需要 Python**。

## 3. Luckfox 操作（日常运行）

### 3.1 部署并运行 Python 脚本（推荐）

在 Ubuntu VM（或 Mac）上，把脚本传到板子，再 SSH 上去跑：

```bash
# 在 VM 上（脚本文件放在 VM 本地，内容见下）
scp serial2tcp.py root@<luckfox_wifi_ip>:/root/

# SSH 上板子
ssh root@<luckfox_wifi_ip>

# 在板子上跑
python3 /root/serial2tcp.py
```

脚本 `serial2tcp.py` 内容：

```python
#!/usr/bin/env python3
import sys, socket, serial

SERIAL_DEV = "/dev/ttyS3"
BAUD       = 115200
PORT       = 9000

def main():
    dev  = sys.argv[1] if len(sys.argv) > 1 else SERIAL_DEV
    port = int(sys.argv[2]) if len(sys.argv) > 2 else PORT
    try:
        ser = serial.Serial(dev, BAUD, timeout=1)
    except serial.SerialException as e:
        print(f"[!] 打开串口失败: {dev} ({e})")
        print("    检查: 1) ls /dev/ttyS*  2) luckfox-config 里 UART3 是否开启")
        sys.exit(1)
    srv = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind(("0.0.0.0", port))
    srv.listen(1)
    print(f"[*] 串口 {dev} @ {BAUD} -> TCP :{port} 就绪")
    while True:
        conn, addr = srv.accept()
        print(f"[+] 客户端 {addr}")
        try:
            while True:
                line = ser.readline()
                if line:
                    conn.sendall(line)
        except (BrokenPipeError, ConnectionResetError, OSError) as e:
            print(f"[-] 断开: {e}")
        finally:
            conn.close()

if __name__ == "__main__":
    main()
```

### 3.2 socat 零代码备选（若镜像有 socat、没 Python）

```bash
socat TCP-LISTEN:9000,fork /dev/ttyS3,b115200
```

一行搞定，作用和上面 Python 脚本一样。

## 4. Ubuntu 22.04 虚拟机操作

### 4.1 网络设置（桥接，推荐）

VM 设置 → 网络 → 改成 **桥接(Bridged)**，让 VM 拿到和 Luckfox 同网段的 IP。

### 4.2 装 nc

```bash
sudo apt update
sudo apt install -y netcat-openbsd
```

### 4.3 确认能连通 Luckfox

```bash
ping <luckfox_wifi_ip>        # 能通再往下
```

### 4.4 收数据

```bash
nc <luckfox_wifi_ip> 9000
```

应每 1 秒看到一行：

```
T=25,H=60,L=75,S=1
```

## 5. 端到端联调（分阶段定位问题）

| 阶段 | 操作 | 通过标准 |
|---|---|---|
| 1. STM32 单测 | PA2 接 USB-TTL 的 RX，PC 串口助手 115200 | 看到 `T=...,...` |
| 2. Luckfox 串口单测 | 板子上 `stty -F /dev/ttyS3 115200 && cat /dev/ttyS3` | 看到同样数据 |
| 3. Luckfox TCP 单测 | 板子上 `nc 127.0.0.1 9000`（脚本已跑） | 看到数据 |
| 4. 端到端 | VM 上 `nc <luckfox_wifi_ip> 9000` | 每 1 秒一行 |

**哪一阶段断了，问题就在该阶段与上一阶段之间。**

## 6. 常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| 收到全是乱码 | **没共地**；或波特率不对（都 115200）；或接线接错到 RX 了 |
| `/dev/ttyS3` 不存在 | UART3 没开启 → `luckfox-config` → UART → UART3 → enable |
| `python3` 报错 / 没有 serial | 装 pyserial，或用 socat 方案（3.2） |
| Wi-Fi 连不上 | 检查 `rkwifi_server` 进程冲突，`killall rkwifi_server`；确认 ssid/psk 无误 |
| VM `nc` 连不上 | 桥接没设好 / IP 不对 / 端口被防火墙挡；先 `ping` 再 `nc` |
| STM32 编译报 `huart2` 未定义 | 没在 CubeMX 生成 USART2；重新生成 |
