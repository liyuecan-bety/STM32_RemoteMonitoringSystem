# STM32F407 工业级数据记录与远程监控终端 — 技术路线

> 硬件平台：正点原子探索者 STM32F407ZGT6
> 开发环境：macOS + 虚拟机（Windows）+ Keil5 MDK + STM32CubeMX
> 项目性质：嵌入式系统综合实战（采集 → 存储 → 通信 → 多任务）

---

## 0. 项目概述

用 STM32F407ZGT6 实现一台「工业级数据记录与远程监控终端」，核心能力：

1. **采集**：ADC 采集光照/电压、DHT11/DHT22 采集温湿度
2. **存储**：数据加时间戳，以 CSV/TXT 存入 SD 卡（掉电不丢）
3. **通信**：通过以太网（LWIP）上报至云端（OneNET/阿里云）或 PC 上位机
4. **系统**：FreeRTOS 四个任务并行，断网数据缓存、恢复后补传

核心亮点（简历/答辩用语）：

- DMA 采样减轻 CPU 负担，为网络通信腾出时间
- FATFS 掉电保护 + 长文件名支持，数据可追溯
- 自定义协议栈 + SD 卡断网缓存，保证数据完整性

## 4. 阶段 1：传感器采集 + 本地显示（约 2 周）

### 4.1 ADC + DMA 采集（光照 / 电压）

**要学什么**

- STM32F407 的 ADC 原理：12 位、扫描模式、规则组/注入组
- DMA 原理：外设 → 内存的自动搬运，减轻 CPU
- ADC 多通道 + DMA 循环传输的配置

**要做什么**

1. CubeMX 配 ADC1，多通道扫描模式 + 连续转换
2. 配 DMA2 循环模式，把采样结果搬进 `uint16_t adc_buf[N]`
3. 光照（光敏电阻/LDR 分压）接一个 ADC 通道，电压（如板载电压）接另一个
4. 用「多次采样取平均」滤波，消除毛刺

**关键点**：DMA 让 CPU 零参与采样，这就是「为网络通信腾时间」的技术落点。写代码时能说出「4 通道采样结果由 DMA2 自动循环搬进数组，主循环只读不采」。

### 4.2 DHT11 / DHT22 温湿度（单总线）

**要学什么**

- 单总线（OneWire）协议：一根线分时传输，靠 μs 级高低电平时间差区分 0/1
- DHT11（整数精度）与 DHT22/AM2302（0.1℃ 精度）的区别

**要做什么**

1. 用 GPIO 模拟单总线时序：主机发启动信号 → 传感器应答 → 读 40bit 数据
2. 校验和验证，读错重试
3. **读取期间进临界区/关中断**，防止时序被打断

**关键点（高频翻车）**：单总线时序是 μs 级，被中断/调度打断就读错。DHT 读取要临时屏蔽中断或用 `__disable_irq()`（读完后恢复）。

### 4.3 LCD 显示

**要学什么**

- 探索者板载 TFT LCD（2.8/3.5 寸），FSMC 接口驱动 ILI9341/类似控制器
- 字符/汉字显示、简单界面布局

**要做什么**

1. 移植正点原子 LCD 驱动（字符显示、清屏、画点）
2. 界面分区：温湿度、光照、电压分区刷新
3. 实时刷新，加一个运行指示灯/心跳

### 阶段 1 验收标准

- [ ]  屏幕实时刷新四项数据
- [ ]  手挡光照传感器，数值明显变化
- [ ]  DHT22 连续 10 分钟读数无错误值
- [ ]  ADC 采样由 DMA 完成，主循环里能看到 `adc_buf` 自动更新

## 5. 阶段 2：数据存储 + 文件系统（约 1~2 周）

### 要学什么

- SDIO 协议（4 线模式）与 SD 卡初始化流程
- FATFS 文件系统：挂载 `f_mount`、打开 `f_open`、写 `f_write`、同步 `f_sync`
- RTC 实时时钟 + 后备电池（探索者板载 CR1220 电池）
- CSV 格式约定

### 要做什么

1. CubeMX 配 SDIO，跑通 SD 卡初始化与读写
2. 移植 FATFS，**开启长文件名 `_USE_LFN`，编入 `cc936.c`（GBK 编码）**，否则中文文件名乱码
3. 配 RTC，生成 `YYYY-MM-DD HH:MM:SS` 时间戳
4. 把采集数据按 CSV 落盘：`时间,光照,电压,温度,湿度` 一行一条
5. 数据攒批 + 定时 `f_sync` 落盘（频繁 `f_open/f_close` 慢且伤卡）

### 掉电保护（亮点）

- RTC 靠电池保持时间，掉电时间不丢
- 数据写完及时 `f_sync`，断电不丢最后一批
- 文件名带日期（如 `DATA_20260826.CSV`），可追溯

### 阶段 2 验收标准

- [ ]  拔电再上电，RTC 时间正确
- [ ]  SD 卡 CSV 用 Excel 打开不乱码、不出现乱码中文
- [ ]  数据连续，无断档
- [ ]  长时间运行内存不泄漏、卡不写坏

## 6. 阶段 3：远程通信 + 多任务（约 2~3 周，最难）

### 6.1 FreeRTOS 四任务骨架（先做，不碰网络）

**要学什么**

- FreeRTOS 核心：任务创建/删除、优先级、调度
- 任务间通信：**消息队列**（传采集数据）、**互斥锁**（保护 SD 卡）、**信号量**（同步）

**要做什么**

1. CubeMX 使能 FreeRTOS（CMSIS-V2 或原生均可，建议 CMSIS-V2 接口更现代）
2. 建四个任务：


| 任务     | 优先级 | 职责                           |
| -------- | ------ | ------------------------------ |
| 采集任务 | 高     | ADC+DHT 采集，发消息队列       |
| 存储任务 | 中     | 收队列，写 SD 卡（互斥锁保护） |
| 通信任务 | 中     | 上报数据（先空转占位）         |
| 显示任务 | 低     | 刷新 LCD                       |

3. 用**消息队列**在采集→存储之间传数据，**不要用全局变量乱传**

### 6.2 LWIP 以太网通信

**要学什么**

- 探索者板载 LAN8720A 以太网 PHY（RMII 接口）
- LWIP 协议栈：TCP/UDP、socket 编程
- MQTT 协议（上云用）

**要做什么**

1. CubeMX 配 ETH + 使能 LWIP
2. 先跑通 TCP 回环（PC 网络调试助手能看到数据）→ 再 UDP → 再上云
3. 用 MQTT 接入 OneNET 或阿里云（参考正点原子 OneNET 例程）

### 6.3 断网续传（核心亮点）

**设计思路**：数据在 SD 卡上带「上报状态」标记，断网时数据照常落盘、不丢；恢复后补传。

```
采集 → 写SD卡(标记"未上报") → 通信任务读"未上报"数据 → 上报成功 → 标记"已上报"
```

**要做什么**

1. CSV 增加一列上报状态字段，或维护一个「待发送队列」
2. 网络断开检测（心跳超时）
3. 重连成功后，按时间顺序补传未上报数据

### 阶段 3 验收标准

- [ ]  四个任务并行、互不阻塞
- [ ]  PC 上位机/云端能收到实时数据
- [ ]  **拔网线 10 分钟，重插后云端能补齐缺失数据**（这是整个项目最能打的证据）

## 8. 常见坑与对策（提前知道，省一周）


| 坑                 | 现象                | 对策                                   |
| ------------------ | ------------------- | -------------------------------------- |
| 单总线被中断打断   | DHT 读数随机错误    | 读取期间关中断 / 进临界区              |
| LWIP 内存不足      | 连不上 / 随机死机   | F407 仅 192KB RAM，heap 严格按例程配置 |
| SD 卡频繁开关文件  | 慢、伤卡            | 攒批 +`f_sync`，别每条数据 open/close  |
| 中文文件名乱码     | CSV 文件名乱码      | 开`_USE_LFN` + 编入 `cc936.c`          |
| 时钟配置错         | 串口乱码 / 外设异常 | 确认外部晶振 8MHz、PLL 到 168MHz       |
| 任务用全局变量通信 | 数据竞争、难调试    | 用消息队列 + 互斥锁                    |
